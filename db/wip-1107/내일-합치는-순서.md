## 주의 (11/07 노트북 점검)
- fix-노트북.sql은 영등포 장소를 하나도 지우지 않아요. 크롤링(07)이 영등포를 다시 넣거나 고쳐도 충돌 없음
- B(날짜 휴무)는 id 목록, F-8(격주·한글날 휴무)은 `주소 NOT LIKE '%영등포구%'`로 영등포를 뺐어요. "서울"·"서울특별시" 둘 다 맞아서 F-5(주소 통일) 앞뒤 순서와 상관없어요
- 그래서 07이 넣은 영등포 장소의 날짜 휴무("월(11/3) 휴무", "금(10/9) 한글날 휴무", "(매달 2, 4번째 …)")는 이 파일로 안 지워져요 → 학원 PC 10에서 처리했는지 직접-체크-쿼리 8번으로 확인하고, 남아 있으면 B·F-8을 영등포 포함으로(id 목록 대신 글자 규칙, 주소 조건 빼고) 한 번 더 돌리기
- 정제 B·C·E·F-1·F-3·F-4는 id로 지워서, 07이 새로 넣은 스터디카페·애견카페 같은 곳은 안 지워져요 → 직접-체크-쿼리 2번(업종 빈도)·17번(묶음 없는 음식점)으로 확인
- F-5(주소 통일)·F-7 "점포별 상이"·F-10(https)·biz-group-매핑.sql은 글자 규칙이라 07 새 장소에도 그대로 적용돼요. biz-group은 목록·규칙에 안 맞는 새 업종이면 NULL → 17번에 나와요
